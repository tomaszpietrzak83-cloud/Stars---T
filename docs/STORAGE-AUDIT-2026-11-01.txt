2026-11-01

Measured workspace: 101.494 GB before, approximately 6.356 GB after cleanup

Actions completed

  year-2477 performance input. All tables/schema/values matched logical SHA-256

- Compacted the active database by making a separately verified VACUUM INTO

  passed. The current compact safety copy remains available privately.
- No personal turn generated, no queue recalculation, no logical game changes.
  Personal game remains year 2477 WaitingForPlayers. Original WineDVM untouched.

Why the database had grown
The previous file was 2,691,682,304 bytes. SQLite reported 572,349 free pages of
4096 bytes each: 2,344,341,504 bytes were reusable free space, approximately 87%.
Rewriting/removing large historical JSON reports and compressing stored reports
had freed pages without shrinking the SQLite file itself. VACUUM INTO rebuilt
the same contents into 330,797,056 bytes (about 315.5 MiB), with zero free pages.

Before compaction, major allocated objects were players ~265 MB, fleets ~54 MB,
planets ~15 MB and ship designs ~8.5 MB. The players table contains each player's
independent reports/messages: fleet intel ~137 MB, planet intel ~40 MB, design
intel ~35 MB and messages ~24 MB. This actual game contains 144 players, 12,600
planets and 41,946 stored fleet/base rows. Large maps and separate knowledge per
player increase real data volume; the former 2.69-GB file was mostly free space.

Why the development checkout is larger than a download
After cleanup the checkout including personal data is ~2.16 GiB. Its data
directory is ~0.66 GiB (compact live database plus retained turn archives).
It also includes development dependencies, Git history, source/build copies and
an installed runtime UI. The wider workspace includes ~2.25 GiB of development
tools and ~1.49 GiB of retained private audit/backup material.
