3. CHANGES AND EVIDENCE
A. cs/patrolsort.go: sortedPatrolTargets, called from
   cs/patrolautomation.go: turnGenerator.planPatrolAutomation.
   The old stable comparator repeatedly called enemyApproachingColony for the
   same contact; each call could scan all 12,600 planet reports. A local map
   remembers that boolean only during one sort. All old ranking criteria,
   distance comparisons, nil placement and stable ties remain unchanged. The
   input intel slice is cloned and no cache survives movement/intel changes.
   The independent original-comparator oracle tests pointer order, equal
   distances, duplicate pointers, nil/stale/deleted reports and refreshed input.

B. cs/universe.go: Universe.addFleet.
   getFleets rebuilt the universe-wide owner index after every single fleet
   append during production. addFleet now extends an already valid owner index
   only when exactly one tail fleet was appended and it is that exact pointer.
   Bulk append/compaction still take the existing rebuild path. Queries still
   filter deleted fleets and return a separate result slice. Tests cover many
   production appends, deletion, reused fleet numbers, other owners, result-slice
   independence, bulk append and compaction.

The 3+3 timings measure A+B together. They are not separate factorial benchmarks
for each change; the CPU call trees support both identified cost reductions.

C. Test-only instrumentation in server/localautomationrepro_test.go and
   server/copyaudit_test.go: optional phase summaries, game-size logging,
   turn-only CPU profiles and bounded-object normalized state hashing/diagnostic
   gzip JSONL. New private output paths must be under audit-results. No production
   logging, API, database schema, report serialization or rules were changed.

Implementation and ownership
- db/turnstatements.go, db/games.go: prepare each distinct Exec SQL statement
  once per UpdateFullGame transaction, reuse it, close it on exit and restore
  the original writer. No writes are skipped or reordered. Read queries still
  use the original transaction. There is no cache across saves/transactions.
- db/playerreports.go, db/games.go: encode the next batch of eight immutable
  PlanetIntels while the caller serially saves the current batch. Existing
  encoding workers remain bounded by min(8, GOMAXPROCS, batch size). An
  unbuffered hand-off permits only the current and next batches to be live.
  On early SQL/encoding failure, stop unblocks the hand-off and joins workers
  before returning. Player IDs/designs and all SQL writes remain on the caller.
  No report fields are mutated during the asynchronous read.
- db/generated/planet_report_storage.go: pool gzip writers to reuse their
  compression tables; reset destinations to io.Discard before returning a writer
  to the pool. Each encoded report retains its own byte buffer. JSON, compression
  level, threshold, magic header, decoder and storage schema are unchanged.
