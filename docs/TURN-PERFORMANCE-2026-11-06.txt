Turn generation performance and failure handling — 2026-11-06

Scope and safety
Only craig-stars sources were edited. Runtime tests use audit backups copied again
into test-owned temporary directories. Input SHA-256 is checked after each test.
No personal database is opened by these diagnostics, no live turn is submitted,
and no live server is restarted. Native candidate is staged separately in
 dist/turn-speed-1106/stars-local.exe.

Reliability
- A failed full-game load after entering GeneratingTurn now sets
  GeneratingTurnError. Missing full-game results return errNotFound instead of
  passing nil onward. A second state-write failure is retained with errors.Join.
- Parallel AI workers clear SubmittedTurn before planning, return errors annotated
  with game/player, join all workers, and aggregate errors in input order.
  Failed AI planning stops before the database transaction and result archive.
  Universe creation also propagates AI errors and rolls back its transaction.
- Tests inject read failure, missing result, state-write failure and partial AI
  mutation; check unchanged year/players/fleets/planets and successful retry.
  A separate test checks multiple workers' errors and host-game rollback.

Performance changes (no rules or thresholds changed)
- Separate orders/result archive phase timings from simulation.
- Frontier scoring indexes current assignments once per invocation rather than
  decoding all fleet tags again for every candidate. Fleet summation order stays
  the same, so floating-point scoring/tie order is preserved.
- Solo patrol assignment indexes claimed targets once per invocation.
- Route search rejects legs already exceeding MaxTurns before threat/fuel work,
  using precisely the prior bound and preserving gate travel times.
- Threat values for the same directional corridor and civilian/combat mode are
  reused only during a single route search. Margin rebuild clears values; entries
  are bounded to 4096 and the prior cache is restored on return. Nothing survives
  into a subsequent search. No simulation random number call was added/removed.

State equivalence and its limit
- Compare every exported player (including AI reports), fleet, planet, starbase,
  wormhole, salvage, minefield, packet and trader, plus the game record.
- Normalize createdAt/updatedAt bookkeeping timestamps, shipDesignIntels ordering
  and ordering within consecutive PlayerDiscovery messages, as in the previous
  performance audit. No physical state, commands or fuel-resume tags are ignored.
- Small input: 33 players, 2617 fleets, 2744 planets and 292 bases; ZERO normalized
  differences, including all other object groups.
- Large input: 33 players, 8492 fleets, 2744 planets and 1027 bases. Eleven fleets
  differ only in tags.automatic-fuel-resume. ALL other normalized fields match.
- Repeating the unchanged baseline independently also differs in that tag for
  seven fleets. Thus whole-state determinism already fails before these changes;
  do not claim byte-identical or fully identical large-game outputs.
- Code inspection points to the unordered `for num := range blocked` loop in
  enforceAutomaticDeparture: releaseTankerCustomers can restore another blocked
  fleet's orders before/after its resume tag is captured. This is a plausible
  mechanism consistent with the baseline repetition, not a newly fixed rule.
  The loop and its behavior were deliberately left unchanged in production.
- 160 seeded route comparisons against the exact original route function PASS.
  Threat-cache tests compare exact reference values across combat/civilian mode,
  margin changes, reuse, cleanup and capacity eviction. All full suites pass.
